# Vivo — how to use

Plan and architecture: [VIVO-PLAN.md](./VIVO-PLAN.md). Code: `k9_vivo/`.

## Start (PC)
```bash
cd k9_vivo && npm install          # first time only
node src/server.js                 # gateway at http://127.0.0.1:3090 (starts DISARMED)
```
The hub (port 3080) must be running: Vivo talks to the robot **only through it**.

Variables (all optional; see [`.env.example`](../.env.example)): `ANTHROPIC_API_KEY` (enables the AI; without it only simple commands work), `VIVO_MODEL` (default `claude-sonnet-5-5`; `claude-haiku-5-5` answers faster), `HUB_TOKEN` (if the hub uses a token), `VIVO_MAX_SPEED` (default 0.5), `VIVO_IDLE_MIN` (disarms by itself, default 10), `VIVO_PORT`, `K9_HUB_URL`.

## Languages
Vivo follows the language chosen in the panel / on its own page (Português, English, Español, Français, Deutsch, 中文): speech recognition and speech synthesis use that language, simple commands and "stop" are understood in it, the fixed replies are translated, and the AI is asked to answer in it. See [`I18N.md`](./I18N.md).

## On the phone (USB, debugging enabled)
```bash
adb reverse tcp:3090 tcp:3090
adb shell am start -a android.intent.action.VIEW -d http://localhost:3090/
```
Open it in **Chrome** (`localhost` counts as a secure address, so the microphone is allowed), tap 🎤 and allow the microphone. Say **"enable vivo"** (or tap *Enable Vivo*) and speak: "sit", "walk forward", "turn left", "dance", "stop".
With the AI key, any sentence works ("could you lie down for a bit?", "what do you do if you reboot?").

## The "K9" Android app (installed over USB): the full-screen panel with a single voice control
Code in `k9_vivo/android/` (Kotlin, no AndroidX). The app is a **full-screen WebView of the hub's real panel** (`http://localhost:3080`): joystick, D-pad, camera, poses, Settings, everything the same as in the browser. **There is no native bar any more**: the only voice control is the panel's **Voice** button (Poses section). Inside the app it uses the native microphone (Android's recognition and voice) through a bridge of **6 methods** (`K9App.ouvir / falar / perguntarIA / armarVivo / pararVivo / idioma`), which only obey while the current page is the local panel. `idioma` accepts only the six supported language tags and sets the recognition/speech language.
- **Icon and name: "K9"** (adaptive icon, white K and coral 9; generated by `k9_vivo/android/icone/gerar_icone.py`). The app's own screens (error page, address dialog) follow the phone's system language (`res/values-*/strings.xml`).
- **Voice router** (in the panel, `nome-voz.js`): 1) *stop* (in any sentence, without the name, never goes through the AI); 2) the name, in continuous listening; 3) **local rules** (free and instant: "sit", "give a paw", "turn on the flashlight"...); 4) **cloud AI, only if you switch it on** in *Settings → Name and voice* (off by default: with it off nothing leaves the PC and a sentence with no rule gets "I did not understand").
- **STOP:** the panel's `Stop` button (small, fixed in the corner) stops the robot **and** Vivo. If the app leaves the screen, the robot stops, listening stops and Vivo closes.
- Voice switches off by itself after 10 min without a command; walking by voice is limited to 10 s per minute; turning NPC mode on turns voice off and blocks the Voice button (NPC does not take voice commands).
- **Works over Wi-Fi, no USB:** the app opens `http://<PC IP>:3080` and Vivo goes through the hub's `/vivo` path (the gateway stays on 127.0.0.1:3090 only). The first time, the app asks for the PC's IP; if the panel does not open, "Try again" and "Change PC address" appear. Phone and PC on the same network.
- **Security:** the WebView only browses `<PC IP>:3080`, and the app only accepts a local-network IP (192.168.x, 10.x, 172.16-31.x) or localhost; no file access. The hub accepts the `/vivo` WebSocket only without an Origin (the app) or from the hub's own origins. Anyone on your Wi-Fi reaches the hub (and Vivo, which starts disarmed): use a trusted network.

```bash
# build (JDK 17 and the SDK live in ~/Android, outside the repository)
cd k9_vivo/android
JAVA_HOME=~/Android/jdk17 ANDROID_HOME=~/Android/sdk ./gradlew assembleDebug
# install (USB needed only this once) and set the PC's IP in the app right away
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n br.k9.vivo/.MainActivity -e host <PC IP>
```
*Current limits:* listening only works with the app **on screen** (no foreground service yet); recognition is Google's (the audio goes to Google's cloud) and it **does not tell who is speaking** (the owner, the TV, music); when nobody speaks, Android restarts listening every ~5 s and on some devices it beeps.

## Robot name and voice in the panel
- The name is chosen in the panel's **Settings → Name and voice** (or `POST /api/nome`) and applies to the panel, Vivo and the app. It is stored in `k9_control_hub/data/nome.json` (outside git; default `K9`).
- **Voice in the panel** (the *Voice* button): simple commands, no AI: "Tobias, sit", "Tobias, walk forward", "Tobias, dance". Without the name the command is ignored (this can be switched off in the settings). **"Stop", "halt", "enough" and similar words always stop, with or without the name** (the exact words per language are in `k9_control_hub/public/i18n/voice-lexicon.js`). Walking by voice uses half the speed limit and lasts at most 3 s.
- The browser's microphone is only allowed on **localhost**: on the PC `http://localhost:3080`; on the phone, `adb reverse tcp:3080 tcp:3080` and open `http://localhost:3080` in Chrome.
- In Vivo, **continuous listening** only obeys if the sentence mentions the name; push-to-talk does not need it.

## How Vivo protects itself
- It starts **disarmed**; arming is by voice or button. It disarms by itself after 10 min without use, when the page closes or if the phone disconnects.
- **"stop", "halt", "enough"…** stop the robot at once, **before** any AI. The page's **STOP** button stops and disarms.
- Only these actions reach the robot: poses (stand, sit, lie down, paw R/L, dance, stretch, wag tail, dig) and walking. Never: calibration, trim, servo test, gait, Wi-Fi, firmware, flashlight.
- Walking: at most 50% speed, 3 s at a time, 10 s per minute; at most 12 actions per minute; always ends with `drive 0`.
- Hub or AI error: it stops and falls back to simple commands. All actions go to `k9_vivo/data/auditoria.jsonl`; memories go to `k9_vivo/data/memoria.jsonl` (both outside git).
- The gateway only listens on `127.0.0.1`, refuses strange `Host` and `Origin` (another site open on the PC cannot control it) and the memory refuses passwords, keys and tokens.

## Use with Claude Code or Claude Desktop (MCP)
The same tool set is an MCP server over stdio. Example configuration (`.mcp.json`):
```json
{ "mcpServers": { "k9-vivo": { "command": "node", "args": ["k9_vivo/src/mcp-server.js"], "env": { "VIVO_ARMAR": "0" } } } }
```
It stays **disarmed** (only `robo_parar`, knowledge and memory work). `VIVO_ARMAR=1` arms at start-up: use it only knowing what you do, with the robot in a clear area.
Tools: `robo_status`, `robo_poses`, `robo_pose`, `robo_andar`, `robo_parar`, `conhecimento_buscar`, `memoria_buscar`, `memoria_salvar`, `falar`.

## Tests
`cd k9_vivo && npm test` (48 tests: safety, simulated robot, RAG, MCP, agent with simulated AI, interpreter, gateway, multi-language voice). The test with the **real AI** needs `ANTHROPIC_API_KEY` and has not been done yet.

## Field test (first time)
1. Robot **in your hand** or suspended, hub and legs online. 2. Say "enable vivo", then "sit", "walk forward" (it walks 2 s at 50%), "stop". 3. Only then on the floor, in a clear area, with someone watching the **Stop** button. 4. On a smooth floor it slips: walk less.

## AI (OpenAI or Anthropic)
Vivo picks the provider from the key it finds, in this order: `ANTHROPIC_API_KEY` (Claude, default `claude-sonnet-5-5`), then `OPENAI_API_KEY` or an `sk-...` key in **`secret.md`** at the repository root (OpenAI, default `gpt-4.1-mini`). `VIVO_MODEL` changes the model (e.g. `gpt-5`). Without a key, or with `VIVO_SEM_IA=1`, only simple commands work. **Local AI (Ollama):** `VIVO_IA=auto` tries this PC's Ollama first (models `llama3.2:3b`/`qwen3:4b` already installed) and uses the cloud only as a fallback; it is off by default because, with the PC busy (load 17 on 8 cores), local answers took more than 25 s. Measure again with the PC idle before adopting it.
- `secret.md` is in `.gitignore` and **was never committed**. The key is never printed nor shown in error messages; it goes only in the `Authorization` header to the provider's API.
- Test with the real AI and a **simulated** robot (nothing moves, costs cents): `cd k9_vivo && node scripts/teste-ia-real.js`. Result of 28/10 with `gpt-4.1-mini`: it sat, walked (the requested speed was cut by the safety layer from 0.5 to 0.25), consulted the documents for a question about rebooting, refused "do a backflip" and "calibrate the servos", and saved a memory.
- What you say goes to the AI provider (transcribed text). It does not receive the hub's token, the Wi-Fi password or anything from `secrets.h`.
